## Who may (role × action)

_Role shorthands: **PLM** = Platform License Manager · **PCFA** = Platform Content Full Access · **PSA** = Platform Settings Admin · **POA** = Platform Operations Admin · **PRA** = Platform Resource Admin · **support** = Platform Support · **account holder** = the user whose account it is, or an admin of the organisation that owns it. Y = may, N = refused, – = not applicable. The evidence line under the table says where each cell comes from._

| action | platform admin roles (which) | platform-license-manager | account admin / owner | space admin | space member | registered | anonymous |

| send a GraphQL document with no credentials and be answered (as anonymous) | – | – | – | – | – | – | Y |
| send a GraphQL document with a guest name and be answered (as guest) | – | – | – | – | – | – | Y |
| send a GraphQL document with a verified session cookie or Hydra bearer | Y | Y | Y | Y | Y | Y | – |

## Where this lands in the new core

The rebuild keeps one GraphQL contract (`schema.graphql`, 002/012) and resolves authorization at read time from the capability ledger instead of stored per-entity policies, so GQL-10/11/12/16/17 survive as behaviours (per-field privilege, one caller per request, `myPrivileges` as the client's oracle, visibility by privacy mode) while the *mechanism* — the stored policy the guard reads, the reset mutations, the "no credential rules" failure in GQL-15 — disappears. Three facts here should shape the core: (1) authentication must keep its three wire states — absent → anonymous, invalid → 401, valid → actor — and the no-oracle property of GQL-04/20 (a deleted account and no credentials look the same); (2) the error contract (GQL-40: `code`, `numericCode`, `userMessage`, `errorId`) is what the client and the support desk already consume, so it is a rebaseline row, not a design choice, and the production-only redaction of GQL-41 must become unconditional (F-1); (3) the endpoint split (GQL-30) and introspection/limits (GQL-31/32) are deployment facts that the new core's API gateway must decide explicitly rather than inherit. Error texts are rebaseline rows, not rules.

## Findings (sources disagree, or likely defect)

1. **Error bodies leak stack traces and internal paths outside production (GQL-41).** Code: the three global filters return the full exception, stack and details unless `NODE_ENV === 'production'`. Test: none asserts the body is clean. Spec/issue: 032 FR-007 promises only `errorId`; server#6663 observed the leak on **acc** on 2026-10-14 ("any server-side error that flows through the global exception handling exhibits the same leakage"). Ruling: route to server#6663 — never a new issue; decide whether acc/prod run with `NODE_ENV=production` and whether the redaction should be unconditional.
2. **Exception messages embed dynamic data (GQL-13/14).** Code: the FORBIDDEN_POLICY text carries the actor id and the policy id; the space not-found text stringifies the lookup options, which are `undefined` on the `lookup.space` path, so callers read the nonsense `… options 'undefined'`. Test: `Requesting a non-existent space…` pins that exact string; `Forbidden…` pins only the code. House rule (`CLAUDE.md:164-174`): never include dynamic data in messages. Ruling: when the messages are cleaned, rebaseline the one case; treat the red as a text change, not a behaviour change.
3. **Not-found and forbidden are distinguishable on lookup (GQL-14 vs GQL-16).** Code: `lookup.space` loads first (10101 for a nonexistent id) and checks `READ_ABOUT` second (11104 for an existing private L1/L2 the caller may not see), so an anonymous caller can confirm that a UUID is a real, private space. Test: the two negatives assert exactly these two different codes, enshrining the oracle. Spec: 107's design intent (SRA-N2, SRB-N2) is "no existence oracle" at the credential boundary; no spec covers the lookup boundary. Ruling: is the existence of a private space (not its content) considered confidential? If yes, lookups should answer not-found for both; if no, record the rule as accepted.
4. **"Public" and "private" endpoints are one endpoint (GQL-30).** Code: one Apollo module; the ingress strips all three prefixes to `/graphql` with the same middleware chain. Test: the harness reads the public configuration document on the *private non-interactive* path without credentials and the public-path tab in the playground is just a label. Spec: none states a difference; the historic difference was the retired Oathkeeper cookie authenticator on `/api/private/graphql`. Ruling: document the aliases as equivalent (and retire the misleading names in the new core), or make the public path reject credentials / the private path require them.
5. **Introspection is on everywhere, by intent (GQL-31).** Code: `introspection: true` without an environment gate, commit message "so gql schema is visible"; GraphiQL and the playground are served and routed. Test/spec: none for production. Ruling: product/security statement whether production exposes the schema and the GraphiQL page (the schema is public in the repo anyway, so the exposure is the playground, not the SDL).
6. **No depth, complexity or rate limit at the application layer (GQL-32).** Code: `plugins: [ApmApolloPlugin]` only; no throttler; `mcp.rate_limit` configured but unenforced. Spec: 008 relies on "a per-source-IP rate cap at the edge" as a stopgap (#1956). Test: none. Ruling: confirm the edge cap exists on acc/prod (ops, outside the three sources — open question 2) and decide whether the new core's gateway owns depth/complexity limits.
7. **Guard test titles and oracles mislead (GQL-16).** Code/test: "Anonymous user cannot access private space data" and "Non-member cannot access private subspace" — the first asserts that the About *is* readable (`READ_ABOUT`), the second asserts only that *an* error exists (no code). Spec: none. Ruling: rebaseline the titles to the rule ("about only" / "refused with FORBIDDEN_POLICY") and tighten the second assertion to the code; no product decision.
8. **`docs/Guest-Users.md` is stale (GQL-05).** It documents a `whoAmI` query and an `OryStrategy` that no longer exist (`schema.graphql` has no `whoAmI`; the guest resolution lives in `auth.interceptor.ts:296-302`). Ruling: fix the doc; the behaviour stands.
9. **Space `READ_ABOUT` for anonymous on a private L0 is a design, not a leak (GQL-16).** Code: anonymous and registered non-members receive `READ_ABOUT` on a private L0 and nothing on a private L1/L2. Test: pinned in both files. Spec: the space table owns this; recorded here because a reviewer of this area will otherwise read the test title as a failed denial. Ruling: none here — cross-reference to the journey table.
10. **Authorization refusals are HTTP 200, authentication refusals 401 (GQL-43).** Code: only `AuthenticationException` sets `extensions.http.status`; the comment in that file says FR-024b wants "authn (401), authz (403) and system (500)" distinguishable on the wire, yet `ForbiddenAuthorizationPolicyException` sets no status, so a FORBIDDEN_POLICY ships as 200 + envelope. Test: the guard test does not assert the status; SRA-N2 asserts 401 for authn only. Spec: the FR-024b spec is not in the local tree (open question 5). Ruling: is 200-with-envelope the intended authz answer (the client relies on it) or should authz be 403 as the comment claims?

## Gaps (no legacy case)

Untested rules by id: GQL-03 (cookie and Hydra bearer paths), GQL-05, GQL-06, GQL-07, GQL-08, GQL-09, GQL-18, GQL-22, GQL-31, GQL-33, GQL-34, GQL-42, GQL-44; plus the untested clauses of GQL-40 (`numericCode`, `userMessage`, `errorId` present) and GQL-43 (FORBIDDEN_POLICY and not-found are HTTP 200; store outage is 503).

Behaviours the area has that neither reading nor tests pinned down:
- A Hydra bearer with a valid signature but an audience outside the allow-list, or without `alkemio_actor_id` → 401 with the specific `error_code` (only garbage and unsigned tokens are exercised).
- A valid bearer for an actor that is not a user (organisation, VC, space) — what `me` and the gate do with it.
- A guest-named request on a resource with a guest policy versus one without (`GLOBAL_GUEST` vs `GLOBAL_ANONYMOUS` outcomes).
- Variable-coercion sanitisation (GQL-42) — a malformed variable must not echo the value.
- An unhandled error's `UNSPECIFIED` + `errorId` shape (GQL-44).
- `AUTHORIZATION_INVALID_POLICY` on an entity whose policy has no rules (GQL-15) — the reset-worker drift case the memory notes describe.
- Subscriptions: a `connectionParams` bearer is ignored; a socket past the absolute ceiling closes (GQL-08).
- Session-store outage 503 on the GraphQL transport (GQL-07) — unit-tested in the server only.
- The non-interactive login refusals (GQL-09): 404 when disabled, 401 `invalid_credentials`, 429.
- Body-size refusals (GQL-33): a document above 64 MB, an MCP body above 256 kB, an upload above the file limit.
- REST guard semantics (GQL-18): 401 vs 403 on the three guarded routes.
- That a field *without* a privilege declaration is served to anonymous (the negative half of GQL-10) — the configuration case proves one instance only.
