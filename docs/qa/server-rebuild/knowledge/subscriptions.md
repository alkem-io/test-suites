# GraphQL subscriptions — behaviour knowledge

_Extracted 2026-11-06 from three sources: server develop @ `eeecf9ddb` (Release/79) code + `schema.graphql`; the legacy server-api suite (`server-api/src/functional-api/subscriptions/`, 3 files, 5 cases, 0 skipped — on demand, not on the nightly); the specs, issues and docs listed in § Sources. Scope: the WebSocket transport and its authentication, the fan-out across server replicas, and for each of the 11 subscriptions who may subscribe, which events reach whom, and what the payload is. Conversation events (COM-55…61), room message rules (COM-11) and in-app notification content (notifications area) are only cross-referenced. This area is **recorded, then retired**: the rebuild drops GraphQL subscriptions (catalogue OP-3). WHAT and WHY only — no mutations, fixtures or request params. Status legend: **proven** = a green legacy case asserts it; **untested** = code and/or spec only, no case; **disputed** = sources disagree, see § Findings; **unknown-why** = the rule holds but no source states the reason — the reviewer fills the why or writes "unknown, ask product". Evidence paths are relative to the server repo unless prefixed `test ›` or `spec ›`._

_Review load: 9 findings · 2 unknown-why rows · 10 untested rows (gaps; 6 more rows are disputed) · 18 constants to tick · 5 open questions. Manual points sit in five places: the Findings, the `unknown-why` rows, the `untested` rows (repeated under Gaps), the "product must rule?" column of the constants, and the Open questions._

## Where this lands in the new core

Nowhere, by design: catalogue OP-3 marks all 11 GraphQL subscriptions **dead-by-design** — chat goes Matrix-direct from the browser (the core becomes the AppService), and every other live update becomes `node(id)` polling with backoff; the row is the first entry of the W4 expected-loss list (decision 8). So the rules above are recorded to make the retirement explicit, not to be reimplemented. What must survive as a behaviour, re-homed: SUB-13/14 (room and conversation events) become Matrix room timelines read directly by the client — their oracle moves to the Matrix client in the harness (plan § W2 `harness-core`); SUB-10/11/12/15/16 (activity, subspaces, posts, forum, VC state) become polling — the catalogue says "the UI behaviours they fed (live updates) need a polling-aware oracle", so each needs a stated staleness bound before a W2 walk can assert "it appears"; SUB-17 (in-app bell) and SUB-18 (polls) follow the same polling rule with their own areas' content rules; SUB-01/02/03 (socket authentication) disappear with the socket — the equivalent in the new core is the one SQL authorization verdict per request, which also closes F-2 (query vs subscription gate drift) and F-8 (anonymous live streams) by construction. Three facts found here should go to the retirement note: (1) the legacy proof is thin and stale (five cases, two of which cannot validate — F-1; off the nightly), so there is no regression baseline to preserve; (2) the broker-backed fan-out (SUB-07/08) is the only place the server holds raw AMQP connections — their removal is a resilience win in itself (007); (3) the push is not transactional with the write anywhere (fire-and-forget after save, Matrix echo for rooms), so a polling oracle with a bound is no weaker than what exists.

## Findings (sources disagree, or likely defect)

1. **The two subspace-created legacy operations cannot validate against the Release/79 schema (SUB-11).** Code/schema: `scalar UUID` only; `subspaceCreated(spaceID: UUID!)`. Test: `subscription-queries.ts:1` declares `$spaceID: UUID_NAMEID!`, `:11` calls `subspaceCreated(subspaceID: …)`. The project is off the nightly, so the inventory's "0 skip" is collection, not execution. Ruling: treat SUB-11 as unproven; fix or retire the two files with the area.
2. **The activity subscription has a weaker gate than the activity query (SUB-10).** Code: `activityCreated` checks read on the collaboration only; `activityLogOnCollaboration` first requires the platform's "read users" privilege (signed-in). Test/spec: none. Ruling: an anonymous visitor can stream a public space's activity (with actor names) it cannot query — align, or accept until retirement.
3. **Posts on draft callouts are pushed (SUB-12).** Code: the post-created event is published before the PUBLISHED check that governs the activity entry and the notification. Test: the Form control only. Spec: CAL-30's "on a published collaboration callout" wording covers activity, not the push. Ruling: whether a draft's posts may reach subscribers (today only those with read on the draft — admins and the creator).
4. **"Discussion updated" fires only on creation (SUB-15).** Code: one publish, in `createDiscussion`. Test/spec: none. Ruling: rename/document, or accept with retirement.
5. **Dead topic and queue constants (SUB-20).** Code: `PROFILE_VERIFIED_CREDENTIAL`, `SUBSCRIPTION_WHITEBOARD_CONTENT`, `SUBSCRIPTION_WHITEBOARD_SAVED` bound to nothing. Ruling: expected-loss list.
6. **Comment removal is never pushed to live activity subscribers (SUB-21, ACT-13).** Code: `messageRemoved` hides the row and leaves the publish commented out ("todo"). Ruling: accept until retirement; note for the polling oracle (hidden rows must disappear on the next poll).
7. **The legacy WebSocket protocol is still served (SUB-04).** Code: `subscriptions-transport-ws` next to `graphql-ws`, both authenticated from the upgrade. Test/spec: none. Ruling: is any client still on the legacy protocol? Retire with the area.
8. **Anonymous visitors may open live streams on public resources (SUB-22).** Code: the gates are the resources' read rules; the matrix grants read on public rooms, collaborations, callouts and spaces to anonymous. Test: no anonymous subscription is attempted. Spec: none. Ruling: by design (public is public) or not — the polling-aware oracle in the new core must know.
9. **Event ids are not unique (SUB-19).** Code: random 0..1000. Harmless (logging only) but a client de-duplicating on `eventID` would drop events. Ruling: note for retirement; no client reads it.

## Gaps (no legacy case)

Untested rules by id: SUB-01, SUB-02, SUB-03, SUB-06, SUB-07, SUB-08, SUB-09, SUB-16, SUB-17, SUB-18; the unknown-why rows SUB-04, SUB-19; the disputed rows SUB-10, SUB-11, SUB-15, SUB-20, SUB-21, SUB-22; plus the untested clauses of SUB-05 (every read-based refusal), SUB-12 (draft callout posts), SUB-13 (edits, deletions, reactions, receipts — see COM-11).

Behaviours the area has that neither reading nor tests pinned down:
- A credential offered only in the handshake payload being ignored (SUB-01) and a socket without credentials running as anonymous (SUB-02).
- The 4401 "Session expired" close after the absolute session lifetime (SUB-03).
- A non-member refused a private space's activity / subspace / post / room subscription; an anonymous socket accepted on a public one (SUB-05, SUB-22).
- `activityCreated` at all — never subscribed by any test (catalogue CT-12 "unreached"); `includeChild` filtering per event; the type filter.
- A subscriber on one replica receiving an event published on another (SUB-07); behaviour after a broker drop (SUB-08).
- Forum, virtual-contributor and poll subscriptions (SUB-15/16/18) — no server-api case anywhere; polls have no legacy area.
- The in-app subscriptions' delivery to the receiver only (SUB-17) — the notifications area reads the counter through queries, not the push.
- Retirement acceptance: for each client feature that consumed a push (dashboard activity, subspace list, post collection, forum, VC status, bell, polls, chat), the staleness bound the polling oracle will assert.
