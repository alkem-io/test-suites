_Extracted 2026-11-06 from three sources: server develop @ `eeecf9ddb` (Release/79) code + `schema.graphql`; the legacy test suites (no `server-api/src/functional-api/innovation-flow/` cases exist — only a helper file; catalogue SP-8 is **partial**; the proof below is drawn from 7 journey, 3 callout-transfer, 1 templates and 2 orphan-free-deletion files, 20 cases, plus 3 client-web walks); the specs, issues and docs listed in § Sources. ## Who may (role × action)

## Where this lands in the new core

Catalogue SP-8 lands as a **stage vocabulary on the space, with `post.stage_id`**: states become `stage` rows and a callout's flow-state tagset becomes a foreign key, not a name. Every rule above stays a behaviour; what changes is that the whole family of name-keyed problems disappears — FLW-04 (the vocabulary that drifts from the flow), FLW-05 (rename must re-point every callout), FLW-15/16 (matching by name, defaulting by name), FLW-03's case-insensitive uniqueness — because a stage has an id. Three facts found here should shape the model: (1) "the first state" is load-bearing on every layer (FLW-09, FLW-13: subspace sidebars belong to positions, the default and reflow target is position 1), so position must be a stable, tie-broken column, not a float with duplicates (register L5); (2) the current state is a pointer that today can dangle (FLW-07) — in the new core it must be a non-null FK with ON DELETE handling decided (first remaining stage) rather than a nullable uuid; (3) the per-state settings are presentation and navigation only (FLW-11, FLW-14) — the new core should keep them out of authorization by construction, and the sidebar vocabulary is a client contract the server only validates. The W4 register's stage mapping must key on the flow's state names, never on the stale template (L1 ruling **R**).

## Findings (sources disagree, or likely defect)

1. **Adding or deleting a state leaves the callouts' vocabulary stale (FLW-04).** Code: `createStateOnInnovationFlow` and `deleteStateOnInnovationFlow` never call `updateFlowStatesTagsetTemplate`; only rename and wholesale replace do. Test: none (the positional-delete cases read states, never the template). Spec 104 Edge Cases: "adding/removing a tab must keep the InnovationFlow's flow-state tagset template's allowed values in sync". Data: 1,100 flow-state tagsets outside `allowedValues` on ACC (register L1), reproduced live as a space admin. Ruling: already filed as server#6729 — keep; for the new core the stage mapping must key on the flow's states (L1 ruling R).
2. **A renamed state's callouts are never re-tagged on the server (FLW-05).** Code: `updateTagsetsSelectedValue` sets the renamed tag in memory and `continue`s before any save; neither the template nor the flow cascades to tagsets, and the only save after it is the flow's. Test: the unit test asserts the in-memory value; `transfer-callout-changed-flow` renames a state in set-up and asserts nothing about existing callouts; no client walk renames a tab with posts in it. Spec 021 Assumptions: "Renaming a phase already re-tags its posts (both platform-side and in the admin UI flow)". Ruling: verify live (rename a tab holding a post as an admin through the API, then list the tab) — if the post vanishes it is a defect of the same family as #6021/#4970 and explains part of register L2 (14 callouts on a vanished state); if the client re-tags, record the server rule as "the client does it".
3. **Deleting the current state leaves a dangling pointer (FLW-07).** Code: the delete never touches `currentStateID`; the field resolver answers null when states are eager-loaded and throws otherwise. Test: the first-phase delete cases delete the current state of a fresh flow but never read `currentState` afterwards. Spec: none (104 edge case "the current-state pointer must remain valid" after add/remove is the only statement, and it is on the opposite side). Ruling: defect — select the first remaining state on delete, as the wholesale replace already does.
4. **A sidebar-only save racing a rename is lost (FLW-12).** Code: read-modify-write without a lock. Test: US2-AS6 pinned red and skipped by decision (2026-10-01). Spec 040 FR-014 / 021 FR-013. Ruling: already filed as server#6571 — keep the skip until it ships.
5. **New callouts default to a state that is not the current state (FLW-16).** Code: the vocabulary's default is set at creation (first state) and only rewritten on rename/replace (to the then-current state); selecting a current state leaves it. Test: none (every transfer case computes "default" as the first state name, which is correct only because nothing re-selected the current state). Spec: none says which state a new callout should land in. Ruling: define "default state for new posts" — first, or current — and make the one write path honour it.
6. **Spec 104 contradicts the code on the L0 floor (FLW-01).** Spec 104 FR-002/006/008: minimum 4, fixed first four phases preserved on template apply. Code: min 1, fixed 0, wholesale replace (server#6418 for client-web#9528, product-approved per the test headers). Test: `apply-template-l0-wholesale-replace` (R-22) proves the code. Ruling: amend 104 (or mark it superseded) so the W1 why column does not cite a dead requirement.
7. **A deprecated field is past its removal date (FLW-26).** Code: `calloutDescriptionDisplayMode` on the space settings carries `REMOVE_AFTER=2026-10-31` and is still served on 2026-11-06. Spec 021 FR-008 asked for "a scheduled removal note"; server spec 010 enforces the workflow. Ruling: remove or re-date.
8. **`update-innovation-flow` is granted and never checked (FLW-27).** Code: privilege rule CREATE → UPDATE_INNOVATION_FLOW exists; no resolver or service reads it; every flow mutation gates on CREATE/DELETE/UPDATE. Test/spec: none. Ruling: drop it (and its policy rule type) or make the state mutations use it.
9. **An empty state name is accepted (FLW-03).** Code: the create input has no non-empty check; the comma and uniqueness checks pass `''`; the client form validates. Test: none. Spec: none. Ruling: add a server-side non-empty rule (a tab with no name cannot be addressed, and the name is the classification key).
