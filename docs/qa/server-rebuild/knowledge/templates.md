## Where this lands in the new core

The briefing keeps the concept — "template = blueprint under its scope; `template_default` per slot and stage" (catalogue CT-14, slices 10–12, marked **full**) — while the things a template is made of change underneath it: callouts, contributions and posts become one recursive `post` with a kind, flow states become `stage`, tagsets/classifications become vocabulary + label, and stored authorization policies disappear. Every rule above stays a behaviour: the six kinds and their payload checks (TPL-01), the three homes with the root-space library (TPL-02), capture-strips-everything-personal (TPL-19), the four apply modes and their order (TPL-25), the default chain for a new space (TPL-27) and the seeds (TPL-31). What should change shape: (1) the content space is today a parallel copy of the space model (own collaboration, about, settings, licence — TPL-22/23, and the 310 orphans of finding 4); in a one-`space`-document core a space template is a stored document of the same shape, which removes the fixed content-space licence and the two-level depth limit; (2) the template default becomes a per-slot/per-stage reference, so TPL-17 (default post template per stage) and TPL-30 (slots) are one mechanism; (3) the file repair (TPL-35) is a legacy-era correction and should not be carried — files upload straight to the container and the ETL must copy template files once; (4) reading a template from its set's policy (TPL-33, client-web#8804) becomes a scope rule on the blueprint. Error texts are rebaseline rows, not rules.

## Findings (sources disagree, or likely defect)

1. **The overall template count leaves classification templates out (TPL-04).** Code: `templatesCount` sums five kinds (`templates.set.service.ts:238-276`); the set exposes `classificationTemplatesCount` separately; the library's "number of templates" ordering (IPK-04) uses the same sum. Test: per-kind counts only. Spec: 024 adds the kind, says nothing about the total. Ruling: include the sixth kind, or document the total as "content templates".
2. **The client test plan assumes subspace libraries (TPL-02).** Code: only a top-level space gets a templates manager; `Space.templatesManager` on a subspace returns the root's; the templates-set policy is cascaded on L0 only (`space.service.authorization.ts:536-553`). Test: none. Spec: 024 FR-007a (root library). The client plan `plans/templates-test-plan.md` §7.2–7.3 expects "subspace templates not visible in the parent" and "each level can access own + parent templates". Ruling: strike the plan rows; record TPL-02 as the rule.
3. **A flow state's default template is not read-checked (TPL-17).** Code: `setDefaultCalloutTemplateOnInnovationFlowState` checks UPDATE on the flow state and only that the template exists and is a callout kind (`innovation.flow.service.ts:375-451`, `innovation.flow.resolver.mutations.ts:247-269`); the template's `callout` field is unguarded, so a space admin can point a state at any callout template id (a private space's, the platform library's) and every reader of the flow state can then read it. Test: none. Spec 029 §5: "admins can use any template visible to them". Ruling: add a READ check on the template (as the applier and create-from-template do), then verify live.
4. **Orphan template content spaces on ACC (TPL-08, TPL-21).** Code: delete cascades the whole tree (`template.content.space.service.ts:208-296`, two levels) and update-from-space deletes subspaces before rebuilding (`template.service.ts:674-679`). Data: W4 register F4 — 310 of 465 `template_content_space` rows referenced by no template, L7 — 144 L1/L2 rows without a parent. Test: none walks the rows. Ruling: find the generator (an abandoned rebuild, a failed create whose rollback did not reach the subspaces, or a third-level subspace the two-level load never sees) before the ETL decides what to drop.
5. **Office-document callouts are dropped from a captured space while a callout template may carry a document (TPL-14, TPL-19).** Code: `input.creator.service.ts:192-201` skips `COLLABORA_DOCUMENT` callouts "not templatable"; `createTemplate(file)` accepts one. Spec 085 §0.3/R6: deliberately left so, follow-up on epic #1843. Test: `collabora-template-isolation` proves the upload path only. Ruling: record as a limitation (today) or schedule the lift.
6. **A template content space is hard-coded as office-documents-enabled (TPL-22).** Code: `template.content.space.service.ts:467-471` enables the flag while the owning space may hold no such entitlement; the gate is re-applied only when the template is used (TPL-15, ENT-32). Test: none. Spec 002/085: the subscription boundary is the live collaboration. Ruling: harmless by design, or should a template inherit the entitlements of the space it was captured from?
7. **The "utilization in posts" cases prove nothing about templates (TPL-10).** Test: the posts are created with no reference to the template, then the template is edited or deleted and the post is re-read unchanged — true by construction because the server stores no link. Code: `postDefaultDescription` is read only by the client (029 §4) and the MCP template navigator. Ruling: keep TPL-10 as the rule, retire or rename the three cases so they stop reading as proof of a pre-fill.
8. **Two refusal cases are skipped because the refusal leaves an orphan space (TPL-27).** Test: `space-templates-poll-form` › the two "a FORM in the create-… request itself is refused" cases are `test.skip` until server#6648; the refusal itself is correct but the space row is already persisted with an empty policy and blanks Explore for everyone. Code: `space.defaults.service.ts:52-62`. Ruling: track #6648; un-skip when it lands (cross-reference `test-env-broken-space-explore` memory).
9. **Who may browse the platform library is unclear (TPL-33).** Matrix: `platform/template` grants READ to platform content-full-access only (`access-matrix.md:248-271`), yet `Platform.templatesManager` carries no field guard while every child does; spec 029 §5 says admins "see templates from `platform.library.templates`" — the innovation library (packs), not the platform templates manager. Code: the platform defaults are used without a READ check (`space.defaults.service.ts:187-221`), so ordinary creation works. Ruling: is the platform templates manager an admin-only backstage (today's reading) or a browsable library?
10. **Callout template with a whiteboard framing shows no preview (client-web#10283).** Issue: the template preview renders the "Whiteboard" placeholder, a standalone whiteboard template gets its preview; reproduced on release/75. Code read here: the server stamps whiteboard previews through the whiteboard service for both paths; whether the framing preview URL is left empty by the server or dropped by the client was not determined. Ruling: route to the client-web owner; cross-reference `templates-CRD/callout-tests.spec.ts` "Framing: Whiteboard" cases.
11. **Kind-mismatched update payloads are ignored silently, except classification data (TPL-06).** Code: a `postDefaultDescription` sent to a whiteboard template, or a `sourceWhiteboardID` to a post template, is dropped (`template.service.ts:512-540`) while `classificationData` on a non-classification kind is refused (`:495-504`, I-9). Test: `templates/template.request.params.ts:108-132` `updateWhiteboardTemplate` sends a post description to a whiteboard template and nobody notices. Ruling: refuse every off-kind payload (one rule), or document the ignore.
