## Where this lands in the new core

The briefing folds the community and role set into **credentials on the space** and the organisation (one `credential` row per actor × resource × role, no derived `space-subspace-admin` / `account-admin` rows and no stored `parentCredentials` — the hierarchy is walked by the SQL verdict), applications and invitations of every kind into **one `membership_request`** with a direction (in = application, out = invitation) and a plain state, the membership policy and the "allow subspace admins to invite" switch into `credential_allowed_role` rows, and the stored authorization policies and every reset mutation into a single SQL verdict over the rule tables (catalogue MB-1…MB-9, slices 6–7). Every rule above stays valid as a behaviour; what changes is that RS-07/RS-76 stop being data (A1/A3/A7 vanish), the lifecycle states (RS-23/RS-37) collapse to the request's state, the rejected-but-open asymmetry (F-8) must be decided rather than inherited, the email (platform) invitation tokens are a continuity item at cutover, the Support audit rows (RS-60) must be re-homed in the ops namespace, and the six platform assignment rules (RS-71) become constraints on credential writes. The `_inventory` cases above are the acceptance backlog for slices 6–7; the four open defects (F-3, F-4, F-5, F-13) must be settled before the ETL copies the credentials they shaped.

## Findings (sources disagree, or likely defect)

1. **"Requires the entry role" is declared but never enforced (RS-04).** Code: no check on the assign path; the flag only filters the elevated-role candidate list. Test: suites routinely make personas admin-not-associate / owner-not-admin and nothing refuses it. Spec 062: "each requiring the entry role by declaration though not enforced at assignment". Register: A5 (67 space lead/admin without member, 45 of them organisations), A6 (757 owner/admin without associate). Ruling: enforce (and repair), or drop the flag and document "admin need not be a member".
2. **Removing a role that is not held is refused at the minimum, silently accepted otherwise (RS-06).** Code: the minimum is compared with the current holder count, not with whether the actor holds the role. Test: only a teardown comment. Spec: none. Ruling: removing an unheld role should be a no-op (idempotent like assign) — rebaseline the error.
3. **Organisation invited to L1 ends up in L2; removal from L2 strips L1 (RS-18, RS-52; server#6710, open).** Code: the ancestor walk grants upward only and the cascade revokes downward only, so neither explains it; the issue's own pointers suspect a read-side artefact. Test: `invitation-organization-subspace` proves the L2 → [L0, L1, L2] case; no case pins L1 → not-L2 or L2-removal-keeps-L1. Ruling: reproduce (dev note: not reproduced locally 2026-10-23, real defect there was a stale membership cache after an incomplete removal) and pin.
4. **Invitee standing is never withdrawn on decline or revoke (RS-36; server#6731, register A9).** Code: only the accept path removes `space-invitee`. Test: none reads the credential. Spec 061/081: silent. Ruling: revoke on delete/reject (and on account deletion), then purge the 56 stale rows.
5. **Parent credentials point at the old L0 after a move (RS-74; server#6592, register A3).** Code: the move re-parents without the roles loaded, so `setParentRoleSetAndCredentials` writes nothing. Test: `journey/conversion/move-*` do not read `parentCredentials`. Spec 030 FR-005 says they must be consistent. Ruling: fix; and the ETL must not translate stored `parentCredentials` into grants.
6. **147 subspace admin roles carry an ancestor's member credential as parent (RS-76; register A1, crosscheck F7).** Code writes the same-named parent credential (admin → admin); the rows are legacy data. Ruling: data repair on ACC and PROD before cutover; the matrix cells for `space-member@L0` on L1/L2 resources are the target.
7. **Stored role definitions drift from the code (RS-02, RS-77; crosscheck F4).** Code: caps in the definitions files. 8. **A rejected request stays "open" on a space but not on an organisation (RS-26, RS-37).** Code: deliberate, scoped to organisations with a comment; space keeps archive-then-re-invite. Test: both halves proven on their own side; the space "rejected still blocks" half is not pinned. Spec 061 R4 documented the space route as archive-first. Ruling: with one `membership_request` the new core needs one answer — does a decline/rejection end the request?
9. **An approved application produces the generic "new member joined" but no application-approved event (RS-31; server#6476, open).** Code: `CommunityMembershipOrigin` has no `APPLICATION` member; 061 R40 restored R31. 062 FR-010 wants "someone joined" on approval for organisations (consistent) and R48 leaves it an open product question. 11. **Owner minimum of 1 is only enforced on removal (RS-54; register E2).** Code: creation grants associate + admin, never owner; 126 ACC organisations have no owner, 40 neither owner nor admin, 11 of 23 2026 organisations no roles at all (created without an actor).
