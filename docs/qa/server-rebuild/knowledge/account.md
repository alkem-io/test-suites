## Where this lands in the new core

The account becomes the owning `actor` row's host record: `account(id, host_actor, type, billing_ref)` with resources (`space`, `virtual_contributor`, `innovation_pack`, `innovation_hub`) carrying an `account_id` foreign key, and the account-admin relation derived at read time from "host = me" or "I am admin/owner of the host organisation" rather than a stored `account-admin` credential (catalogue: credentials become derived; `plan_assignment` replaces the licence snapshot — see entitlements § Where this lands). Three facts found here should shape it: (1) the reach-through to the account (ACC-06, F-1) is a stored-policy artefact — in the new core the account's read rule must be the same whichever edge you arrive by, and the profile's hosted-resources tiers (ACC-08) should be the one read model for "what does this host show"; (2) transfers (ACC-11/12) must be an L0-only, two-consent operation that re-derives entitlement usage on the target (today limits are silent, F-4); (3) the implicit organisation account-admin (ACC-03) is exactly the kind of derived credential the new core computes instead of storing, so its revoke-only-when-neither rule becomes a join, not bookkeeping. Error texts are rebaseline rows, not rules.

## Findings (sources disagree, or likely defect)

1. **The account is world-readable while the profile pretends it is closed (ACC-06 vs ACC-07).** Code: the account policy grants READ to anonymous and registered (twice), and `Space.account`, `VirtualContributor.account`, `InnovationHub.account` and `lookup.account` return the account with unfiltered lists to anyone who can read the parent. Test: `the full account stays closed to an unrelated registered user` proves only that `Organization.account` is null. Spec: 089 KG-1 calls the null "obscurity, not enforcement" and leaves it to a separate ticket (#6129); entitlements F-5 is the same defect seen from the licence side. Ruling: is another host's account (its id, spaces, VCs, packs, hubs, plan, usage) meant to be visible to any visitor? One decision closes F-1 here and F-5 there.
2. **A subspace can be transferred to another account (ACC-13).** Code: `transferSpaceToAccount` accepts any space id, sets `space.account` on it and re-applies its policy; subspaces otherwise derive their account from the top-level space (JRN-15) and `Space.account` is a nullable, SET-NULL relation set only on L0 at creation. Test: none. Spec 030: top-level spaces are transferred, subspaces are moved. Ruling: refuse non-L0 targets server-side (as the moves do, JRN-14), or document the client panel as the only gate.
3. **The VC transfer is declared to return an innovation pack (ACC-15).** Code: `@Mutation(() => IInnovationPack)` on `transferVirtualContributorToAccount`; schema `transferVirtualContributorToAccount(...): InnovationPack!`; the method returns a VC. Test: the A9 group calls it through the generated SDK and reads only `id`. Ruling: schema contract fix (breaking for anyone selecting pack fields; nobody can today).
4. **Transfers ignore the target's licence (ACC-12).** Code: no entitlement check and no licence recompute on any of the four transfers, while creation refuses over the limit (ENT-02/03/04). Test: the positive case is titled "without valid entitlements" and asserts success, enshrining it. Spec: none. Ruling: is a transfer a way around the allowance (and is the resulting over-limit account meant to be read-only, archived or merely unable to create — the same open behaviour as entitlements gap 1)?
5. **Reset skips broken children and leaves their stale rules (ACC-18).** Code: `resilientCascade` logs and returns `[]` for a child that throws a relationship/not-found error, so that subtree keeps whatever rules it had. Data: crosscheck F2 — 1,018 files, 872 buckets, 2,000 tagsets … on ACC still name retired credentials under fresh parents. Test: none. Ruling: accept (inert while nobody holds the retired credentials) or add a "skipped subtree" report to the reset so operators can repair.
6. **Personal-data read decides who sees the full hosted list (ACC-07/08).** Code: the full view keys on `READ_USER_PII`, which space admins of a member and organisation admins of an associate hold.
