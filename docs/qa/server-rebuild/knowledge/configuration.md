## Where this lands in the new core

The document is pure deployment configuration published through the API: it has no entity, no policy and no mutation, so in the new core it is a read-only `viewer`-independent slice served from the gateway's configuration rather than from the domain. What must survive is the *contract* the client already consumes — the eight flag names (typo included, unless deliberately renamed with a client change, F-6), the 24 location keys, the monitoring blocks, the upload ceiling and the language pair — and the one derived table, the visual constraints, which the briefing's `document`/`blob` model should own in one place (today it is copied into every stored visual, CFG-13). Two facts here should shape the core: (1) the upload ceiling is published, enforced and seeded in three places that must agree (CFG-08) — make it one value; (2) the authentication-provider block describes a sign-in path (Kratos public URL) the BFF/OIDC move may have retired (F-7) — decide what the client needs to know at boot before carrying it over. Error texts are not involved; the values are rebaseline rows.

## Findings (sources disagree, or likely defect)

1. **Upload ceiling 20 MB in the test, 15 MB in the code (CFG-08).** Code: `max_file_size` default 15,728,640 since #6196 (`49f96273e`), with the comment that it must equal the bucket default and the middleware guard. Test: the single configuration case pins `maxFileSize: 20971520` (the pre-#6196 value, `26edac549`). Spec: none. No `STORAGE_MAX_FILE_SIZE` override found in the base or test deployment config. Ruling: the test is stale — rebaseline to 15 MB (and confirm that the client's pre-upload check reads this value rather than hard-coding 20 MB).
2. **Banner default aspect ratio 6 in the test, 10 in the code (CFG-11).** Code: `aspectRatio: 10` since `5971a138f` (#6452, 2026-09-02, "make 10:1 the banner default … (was 6)"). Test: TC-03 (`d6dd066c8`, #625, same day, titled "coverage for default 10:1 banner") asserts `aspectRatio: 6` and spells "1200/120/6/6/10" in its title. Spec: client-web#10178 wants the 10:1 default. Ruling: the test pins the pre-#6452 value and should be red on Release/79 — rebaseline to 10 after a live run confirms.
3. **The configuration case can only be green on a local stack, and it hides any sibling (CFG-01…10).** Test: `test.only` on the one case (every other test added to that file would be silently skipped — the banner test was put in a new file for exactly that reason), and `toStrictEqual` against local-stack literals (`domain 'localhost'`, `environment 'local'`, `issuer 'http://alkemio-server-dev/'`, local Kratos URL, `'0'` endpoints). Code/deployment: the test cluster serves `ENVIRONMENT: test` and its own hostnames. Ruling: split the case into shape assertions (keys present, flags in order, types) and a constants probe that reads the expected values from the environment, drop `test.only`, and put the project on the nightly.
4. **The "full configuration" strict-equal is a hand-written subset.** Test: `full-configuration.graphql` omits `language`, `locations.documentation`, `sentry.environment`, `geo.enabled` and `defaultVisualTypeConstraints`, so a change to any of those is invisible; the client-web banner plan already flags the case as "not evidence". Ruling: regenerate the selection from the schema (the lib's codegen) so the oracle covers the whole document.
5. **An unset string setting is published as `"0"` (CFG-06).** Code: the YAML loader converts any value that passes `!isNaN()` to a number, and an unset variable with no default is the empty string, which `Number('')` turns into `0`; the `String!` field then serialises `"0"`. Test: pins `endpoint: '0'` for sentry and apm, enshrining the artefact. Spec: none. Ruling: publish `""` (or make the fields nullable) and rebaseline — a client that treats `"0"` as an endpoint would try to reach it.
6. **`GUIDENCE_ENGINE` is a public enum name with a typo.** Code: `PlatformFeatureFlagName.GUIDENCE_ENGINE = 'guidance-engine'` since #3351; the schema exposes the misspelt name. Test: pins it. Ruling: keep (renaming is a breaking schema change under 002) or deprecate-and-add under the schema-contract rules.
7. **The authentication-provider block still describes Ory Kratos (CFG-10).** Code: one hard-coded provider "Ory Kratos Config" with `kratosPublicBaseURL` and an `issuer` defaulting to `http://alkemio-server-dev/`, unchanged by the OIDC/BFF sign-in work (PR #6143). Test: pins it. Spec: the OIDC spec is not in the local tree (graphql-guard open question 5). Ruling: does client-web still read `kratosPublicBaseURL` at boot (self-service flows: recovery, verification, settings) or is the block dead? Decide before the new core carries it.

## Gaps (no legacy case)

Untested rules by id: CFG-02, CFG-09 (covered by the language area), CFG-12, CFG-13 (covered by the visual area); plus the unasserted parts of CFG-05 (`documentation`), CFG-06 (`sentry.environment`), CFG-07 (`geo.enabled`) and CFG-11 (`allowedTypes` beyond png/jpeg).

Behaviours the area has that neither reading nor tests pinned down:
- A flag flipped in the deployment is reflected on the next request after restart (CFG-02) — no case flips one.
- `defaultVisualTypeConstraints` for the six fixed-shape types (CFG-12) and the invariant `maxHeight = maxWidth / minAspectRatio` for BANNER.
- The `language` block's warning-and-drop behaviour for an unsupported eligible entry and the `en` fallback (CFG-09) — the language suite reads the values but does not provoke an invalid configuration.
- The document on a deployment with Sentry/APM enabled (real endpoints, `submitPII` true).
- That the published upload ceiling equals the enforced one (CFG-08 / GQL-33): upload a file just over the published value and expect the refusal.
- `documentation` URL composition when `endpoint_cluster` carries a port (`https://localhost` vs `http://localhost:3000`).
