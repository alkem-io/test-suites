# Journey — space lifecycle — behaviour knowledge

_Extracted 2026-11-06 from three sources: server develop @ `eeecf9ddb` (Release/79) code + `schema.graphql`; the legacy server-api suite (`server-api/src/functional-api/journey/`, 32 `.it-spec.ts` files, 304 cases, 9 skipped); the specs, issues and docs listed in § Sources. Scope: the L0 space, its subspaces (L1) and sub-subspaces (L2), their identity, creation, settings, visibility, the three same-L0 conversions and the three cross-L0 moves, deletion and reading. Membership, licensing, callouts and notifications are their own areas and are only touched where a lifecycle action changes them. WHAT and WHY only — no mutations, fixtures or request params. Status legend: **proven** = a green legacy case asserts it; **untested** = code and/or spec only, no case; **disputed** = sources disagree, see § Findings; **unknown-why** = the rule holds but no source states the reason — the reviewer fills the why or writes "unknown, ask product". Evidence paths are relative to the server repo unless prefixed `test ›` or `spec ›`. The extraction notes with every file:line are in `journey-dossier.md`._

## Where this lands in the new core

The space document and its tree are slice 4–5 of the rebuild. Everything above stays a behaviour; what should change in the model is what the findings expose: (1) `nameID` uniqueness becomes a database constraint scoped `(levelZeroSpaceID, nameID)` plus a global one for roots (F-7), with the restricted-word list a seed table; (2) nesting depth becomes a constraint on the parent link, not a check in six resolvers (F-3, JRN-14); (3) platform-level access (JRN-30, JRN-49) is derived at read time from the parent chain instead of a persisted record that every move and conversion must remember to recompute (F-4 is the proof that one path forgot); (4) the six conversion/move operations collapse into one "re-parent" command whose semantics follow the one axis the sources agree on — same-L0 keeps the community, cross-L0 wipes it (JRN-40/41 vs JRN-45) — executed in one transaction with the room and invitation side effects as an outbox (F-1, F-5, F-6); (5) licence derivation from the L0 (ENT-26) makes JRN-48 moot. Error texts and the restricted list are rebaseline rows, not rules.

## Findings (sources disagree, or likely defect)

1. **Updates room after a cross-L0 move (JRN-53).** Spec 084 FR-014/015 and SC-003: the announcement room is recreated **empty**; 030 FR-009 makes the UI warn "announcement channel reset". Code: `recreateUpdatesRooms` deletes and recreates it, fire-and-forget after the mutation returns. Tests: four cases named "updates room messages are preserved" pin `toHaveLength(1)` and the `move-L2-to-L1-rooms` header cites epic alkemio#1846 "Updates go with the space". They are green either because the read lands before the async recreate or because the recreate fails silently. Ruling: which is the product rule — preserved or reset? Then fix the losing side (spec+code or the four tests).
2. **Licence after a move (JRN-48).** Code issues the account-type default plans to the moved space's own actor and never recomputes its licence; spec 083 FR-021b asks for explicit propagation; the three "license subscriptions inherited from target L0" cases pass only while the target holds exactly the default plans (a target with Plus would fail). Ruling: define what a moved subspace's licence is (derived from the new L0, per ENT-26) and rebaseline the oracle.
3. **No level guard on conversions or creation (JRN-14, JRN-43).** The three same-L0 conversions accept any space (an L0 given to L1→L0 is renamed with a `-1` suffix; an L0 given to L2→L1 is re-parented under itself); `createSubspace` computes `level = parent + 1` without a cap and the matrix shows `space-admin@L2` holding `create-subspace`; L1→L2 does not check that the source is childless. The moves do all of this. Ruling: file as a defect (hard preconditions on all six, and refuse creation below L2).
4. **Same-L0 conversions do not recompute platform access (JRN-42).** L2→L1 and L1→L2 re-apply authorization from the new parent but keep the stored `platformRolesAccess`; when the new chain differs in privacy this is the #6303 leak class (fixed only for L1→L0 and the moves). No case probes anonymous access after a same-L0 conversion. Ruling: defect.
5. **Atomicity of the L1 moves (JRN-54).** 083 FR-010 "MUST be atomic — single database transaction"; code: role wipe, pending drop, structural writes and plan issue run as separate statements; 030 D-2 records the non-retrofit as risk R-3. Ruling: accept R-3 formally (amend 083) or schedule the retrofit.
6. **Space creation not atomic (JRN-11; server#6648 OPEN).** Community/Matrix outside the transaction, policy applied in a later step; half-created spaces blank list pages and cannot be deleted or repaired. Known defect; no new issue.
7. **nameID uniqueness is check-then-write (JRN-02; server#6730 OPEN).** No unique index for space actors; the L0 check lower-cases stored names, the subspace check does not. Known defect; no new issue.
8. **Parent credentials after a cross-L0 move (JRN-50; server#6592 OPEN).** The moved role set's stored `parentCredentials` keep naming the old L0, so old-L0 admins keep admin-with-parents access and new-L0 admins never get it; four `callout/form/form-space-move` cases are skipped against it. Known defect; also the ACC A1 signature in the matrix crosscheck.
9. **Archived-space expectations (JRN-34).** The six skipped `space-platform-settings` rows expect the harness admin and the licence manager to keep CRUD+GRANT+CREATE_SUBSPACE on an archived space; today's code gives the licence manager `READ_LICENSE`/`READ_ABOUT`/`ACCOUNT_LICENSE_MANAGE` only and members/admins nothing. Ruling: rebaseline when un-skipping; confirm that admins losing *all* access on archive (including reading) is intended.
10. **`Space.subspaces` has no read gate (JRN-63).** Every other content field is READ-guarded; the subspace list resolves for anyone who may read the About (any visitor on a private L0), exposing ids, nameIDs and levels. Not verified live. Ruling: verify; if confirmed, defect.
11. **Mis-targeted skipped case.** `move-L1-to-L2-authorization › cannot target L1 in same L0` is skipped and its body passes a target in a *different* L0; the same-L0 refusal of the L1→L2 move is therefore proven only by code. Test defect; fix when the suite is touched.
12. **Support flag inert on subspaces (JRN-27; crosscheck F8).** The UI offers `allowPlatformSupportAsAdmin` per subspace; the server reads it on L0 only. Already a matrix finding; recorded here because the settings rule depends on it.

Known-defect cross-check: server#6592 → F-8; #6648 → F-6; #6730 → F-7; #6710 (organisation invited to an L1 becomes a member of its L2; leaving L2 removes L1) touches no lifecycle rule here — it belongs to `roleset` and is noted under JRN-13's role chain only.
