## Where this lands in the new core

`callout` is a document kind with a `framing` sum type and a `contributions` relation; `settings` becomes typed columns, not a JSONB blob merged by hand (CAL-12's null and array rules disappear with the blob). Three things found here should shape the model: (1) the per-type contribution rights are decorative today — the new core should either gate per type (and give memo one) or drop the derived privileges and keep the single contribute right (CAL-27, F1); (2) visibility, lock state and framing comments are three independent flags whose enforcement differs (draft rewrites read; lock is checked in one resolver; comments are not enforced at all) — the new core should enforce all three at the same layer (CAL-19/23/24, F2); (3) the collection kinds (Contributors, Subspaces) and the intake kind (Form) are read-time computed or privacy-scoped views with no stored policy — the Form's per-request audience evaluation (CAL-47) is the pattern the new core's `viewer`-scoped reads should follow, and the manual-selection scope guard (CAL-64) and shrink-only render (CAL-66) are invariants, not implementation. Transfer (CAL-70) is a support tool that re-parents a document; with a single store it becomes a parent change plus a classification re-sync, and the activity-log re-stamping goes away. Reactions, votes and responses are each one row per person per target with a unique key — the new core keeps the three upserts and drops the "created vs swapped" timestamp heuristic (`reaction.service.ts:70-75`). Error texts and codes are rebaseline rows, not rules; the Form's `extensions.details.code` convention is the one worth keeping platform-wide.

## Findings (sources disagree, or likely defect)

1. **Per-type contribution rights are never checked (CAL-27, CAL-37).** Code: `allowedTypes` grants `create-post` / `create-whiteboard` / `contribute` rules on the callout, memo none (crosscheck F10), but every contribution mutation gates on `contribute` only; `CREATE_POST` and `CREATE_WHITEBOARD` are checked nowhere. Test: only the contribute refusal is pinned. Spec 016 FR-010 asks for memo authorization consistent with post/whiteboard. Ruling: one right for all types (then drop the derived rules), or real per-type rights (then add memo and gate them).
2. **Framing comments cannot be switched off server-side (CAL-24).** Code: `framing.commentsEnabled` only decides room creation and attachment auth; the room policy is always built. Test: the only cases (`close-state › Discussions`, expecting `CALLOUT_CLOSED` / `FORBIDDEN_POLICY`) are `describe.skip`. Client plan :724-726 only hides the input. Data: audit register F1 — 866 collection callouts on ACC carry `commentsEnabled: true` with no room (2026-07-08 migration); the server creates the room on each one's next edit.
