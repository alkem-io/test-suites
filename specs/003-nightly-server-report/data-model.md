# Data Model: GitHub Pages Report Structure

## Directory Layout on `gh-pages` Branch

```text
gh-pages-root/
├── index.html                          # Top-level index linking to both report types
├── playwright/                         # EXISTING — client-web Playwright reports
│   ├── index.html                      # Playwright summary index (generated by nightly-client-tests.yml)
│   └── <date>/
│       └── <run_id>/
│           ├── index.html              # Playwright HTML report
│           ├── runinfo.txt
│           ├── status.txt
│           ├── commit.txt
│           └── branch.txt
└── vitest/                             # NEW — server-API Vitest reports
    ├── index.html                      # Vitest summary index (generated by nightly-server-tests.yml)
    └── <date>/                         # e.g., 2026-03-16
        └── <run_id>/                   # e.g., 12345678
            ├── index.html              # Vitest HTML report (+ assets)
            ├── runinfo.txt             # Human-readable run metadata
            ├── status.txt              # "passed" or "failed"
            ├── commit.txt              # Full SHA of the tested commit
            └── branch.txt              # Branch name (e.g., "develop")
```

## Entities

### Test Run Report Directory (`vitest/<date>/<run_id>/`)

| Attribute | Type | Source | Example |
|-----------|------|--------|---------|
| date | String (YYYY-MM-DD) | `date +'%Y-%m-%d'` | `2026-03-16` |
| run_id | String | `${{ github.run_id }}` | `12345678` |
| report files | HTML + assets | Vitest HTML reporter output | `index.html`, CSS, JS |

### Run Metadata Files

| File | Content | Format | Used By |
|------|---------|--------|---------|
| `runinfo.txt` | Run ID, date, branch, commit, test outcome | Multi-line key-value | Human inspection |
| `status.txt` | Test outcome | Single word: "passed" or "failed" | Index generator (status icon) |
| `commit.txt` | Git commit SHA | Single line, full SHA | Index generator (short SHA display) |
| `branch.txt` | Git branch name | Single line | Index generator |

### Summary Index (`vitest/index.html`)

Generated dynamically by iterating over all `vitest/<date>/<run_id>/` directories. Displays:
- Runs grouped by date (newest first)
- Per run: status icon, link to report, short commit SHA, branch name
- Navigation link back to top-level index

### Top-Level Index (`index.html`)

Static-ish page regenerated by whichever workflow runs. Links to:
- `playwright/index.html` — Playwright nightly results
- `vitest/index.html` — Vitest nightly results

## Identity & Uniqueness

Each report is uniquely identified by the tuple `(date, run_id)`. The GitHub Actions `run_id` is globally unique per repository, so collisions are not possible.

## Lifecycle

1. **Creation**: Workflow runs → Vitest generates report → workflow copies to `gh-pages-root/vitest/<date>/<run_id>/`
2. **Accumulation**: Each run adds a new directory; previous runs are preserved via `gh-pages` branch checkout
3. **Retention**: Reports accumulate indefinitely (no automatic cleanup per current scope)
